## 交接时必须口头交代的三件事

代码在仓库里，文档在 README 里，但有**三件事写不进代码**，必须当面说：

1. **模板是会过期的。**
   `recruit` 模板里的"招新要求""联系方式"每年都变。
   交接时一定要问：**今年的二维码换了吗？招新人数定了吗？**
   往届二维码贴在新生群扫不进去，是这个包最常见的事故。

2. **不要自己发明数据。**
   年审和立项模板里所有涉及数字的地方（人数、金额、获奖），
   必须来自协会数据目录里的真实记录。**没记录就写【待补】让人去查**，
   不要填一个看起来合理的数。评审是会核对的。

3. **`office-pptx` 技能不是我们写的。**
   它随 DSH 一起来。如果哪天 DSH 升级导致生成 PPT 失败，
   先怀疑那里，**不要改 deck 的代码去适配**。
   deck 只负责把内容准备好，它不碰 pptx 文件格式。
## 改代码之后怎么让它生效（踩过一次的坑）

`file:` 依赖是被**拷贝**进 profile 的，不是软链。所以：

**改完 `lib/*.js`，直接重启 —— 不生效。**
`add` 和 `pnpm install --force` 也都不会重新拷贝（pnpm 只看 spec、不看文件内容）。

必须**先移除再装**：

```powershell
dsh plugin --profile njau remove "@njau-ca/dsh-njau-deck"
dsh plugin --profile njau add "file:D:/.../njau-ca-dsh/packages/deck"
```

判断有没有生效：比一下源码和
`%USERPROFILE%\.dsh\profiles\njau\node_modules\@njau-ca\dsh-njau-deck\lib\`
里同名文件的**字节数**。

> `templates/` 和 `skills/` 是启动时从包目录读的，但那个包目录同样是拷出来的那份，
> 所以**一样要走 remove + add**。
>
> 改完记得跑 `tests/smoke-deck.mjs` —— 它抓出过一个真 bug：
> 模板页标题写的是 `## N. 标题`，解析器却只认 `###`，
> 结果页数一直是 0、日志却照常显示「模板 3 个」。
> 详见 `../../CHANGELOG.md`「冒烟测试抓到的一个真 bug」。
## 这个包最容易在什么时候坏

按可能性排序：

1. **DSH 升级后工具注册契约变了** —— 症状是插件加载了但工具没出现。
   看启动日志里有没有 `[njau-ca] deck 已加载`，里面会报「工具 N」。
   N 应该是 5。不是 5 就是这里坏了。
2. **`templatesDir` 配错** —— 症状是模板列表为空。检查 `cordis.patch.yml`。
3. **数据目录没权限** —— 症状是大纲存不进去。检查 `~/.dsh/njau-ca/deck/` 能不能写。
4. **模板页数变成 0** —— 症状是 `njau_deck_templates` 返回的 `slideCount` 全是 0。
   说明页标题写法没被认出来（编号那行必须以 `##` 或 `###` 开头）。
   跑 `tests/smoke-deck.mjs` 会直接报出来。

排查顺序：先看启动日志 → 再 `njau_deck_templates` → 再手动看数据目录。

## 怎么彻底删掉这个包

`deck` 是完全独立的，删掉不影响任何其它插件：

```powershell
.\scripts\uninstall.cmd njau
```

数据目录里的 `deck/*.json`（往届大纲）**不会**被删。
**删之前先把它们备份出来** —— 那是往届的内容，不是代码。
