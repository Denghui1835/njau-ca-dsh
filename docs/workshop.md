# 计协工作坊（workshop）

> 一句话：**协会的活分三条产线，工作坊是这三条产线共用的那间屋子。**

## 为什么要有「工作坊」这一层

协会的事看起来杂，其实只有三类产出：

| 产线 | 产出物 | 典型场景 |
| --- | --- | --- |
| 办公 | .docx / .xlsx / .pptx | 招新报名表、会议纪要、立项书、报销单、年审材料 |
| 漫剧 | 剧本、分镜、图片、视频 | 招新宣传、活动复盘、公众号内容 |
| 开发 | 网站、工具、脚本 | 协会门户、报名系统、签到工具、练手项目 |

如果每类都做成一个独立入口，新来的人第一周就在问「那个功能在哪儿」。
所以先有一层壳：**一个面板、一个入口按钮、一份现状总览**；壳里再分三条产线。

## 分层与边界

```
┌──────────────────────────── 工作坊外壳 (packages/workshop)
│  只做：看现状（数清楚每条产线有多少东西） + 导航（把面板切过去）
│  不做：不出图、不配音、不剪片、不编译
├──────────────┬──────────────────┬──────────────────┐
│  办公柱       │   漫剧柱（待建）    │   开发柱（待建）    │
│  packages/    │                   │                   │
│  office       │  剧本→分镜→出图     │  文件树 + 编辑器    │
│  ✅ 已通      │  →配音字幕→合成     │  + 终端 + 脚手架    │
└──────────────┴──────────────────┴──────────────────┘
                    共用：<root> = ~/.dsh/njau-ca
                    共用：identity.json（协会身份，唯一真源）
```

**铁律复述**：产线之间不互相调用。外壳要开办公面板时走的是「导航」
（`sidebarRight.openTab('njau-office')` / `window.__NJAU_OPEN_OFFICE__(path)`），
不是 `import` 人家的服务。

## 漫剧柱接下来怎么做（建议路线）

漫剧 = 剧本 → 分镜 → 出图 → 配音字幕 → 合成。每一步都要「看得见、改得动」：

1. **分镜表**：把 `storyboard.json` 的 `panels[]` 渲染成可编辑的卡片
   （镜号 / 画面描述 / 台词 / 时长 / 出场角色），改一格就写回文件。
2. **出图**：每个 panel 一次生成任务，产物落到 `assets/<panel-id>.png`，
   在卡片里预览、重生成、锁定满意的版本。
3. **配音字幕**：按 panel 台词生成音频，时间轴对齐。
4. **合成**：把 panel 图片 + 音频按时间轴拼成视频，导出到 `assets/out.mp4`。

每一步都应该是**一条产线内的插件**，通过 `storyboard.json` 这个文件耦合 ——
而不是互相 import。这样任何一步坏了，其它步还能用。

## 开发柱接下来怎么做（建议路线）

1. 代码编辑器面板（Monaco）：文件树 + 打开 / 保存 / 另存。
2. 与 DSH 自带的终端、文件树面板联动（按 kind 打开，不重造）。
3. 项目脚手架：`site/` 下 `npm create` 或自家模板一键成型。
4. 发布：静态站 → 协会服务器的固定流程，做成一条命令 + 一份检查清单。

## 加一条新产线时改哪里

1. `packages/workshop/lib/lines.js` 的 `LINES` 加一项（id / 名称 / 描述 / 数据目录 / panel）。
2. 建 `packages/<新产线>/`（照 office 的双面包结构：host 管数据与工具，client 管面板）。
3. `scripts/install.ps1` 会自动发现它（只要 `package.json` 里有 `dsh.bundle.patch`）。
4. 更新本文件的状态表 + 那个包的 OWNER.md。
