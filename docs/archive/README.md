# 年度归档

> 每学年结束时，在这里留一份**只读快照**。
> 目的是：十年后有人想知道"2026-2027 届到底做了些什么"，能查到。

---

## 为什么要归档

换届最容易丢的不是代码（代码在 git 里），而是：

- 这一届**做成了什么、没做成什么、为什么**；
- 当时的**插件清单和版本号**（想复现当年的环境时要用）；
- 当时的**真实数据长什么样**（数据结构变了以后，旧数据是怎么组织的）；
- 上一届**想对下一届说的话**。

这些不归档，就永远丢了。

---

## 目录结构

每学年一个文件夹：

```
docs/archive/2026-2027/
├── RETROSPECTIVE.md    ← 这一届做成了什么、没做成什么、为什么
├── plugins.json        ← 归档时刻的插件清单与版本号（可复现）
├── data-snapshot/      ← 协会数据的快照
└── handover-note.md    ← 给下一届的信
```

### `RETROSPECTIVE.md`

至少回答：

- 这一届**做完**了哪些事？
- 哪些事**开了头没做完**？为什么停下的？
- 哪些事**计划了但没开始**？为什么？
- 有哪些**判断错了**的地方？（这一条最重要，也最容易被跳过）
- 下一届**最该先做**的一件事是什么？

### `plugins.json`

```json
{
  "schoolYear": "2026-2027",
  "archivedAt": "2027-06-30",
  "dshVersion": "0.2.0-rc.2",
  "nodeVersion": "v24.21.0",
  "profile": "njau",
  "plugins": [
    { "name": "@njau-ca/dsh-njau-core",  "version": "0.1.0" },
    { "name": "@njau-ca/dsh-njau-brand", "version": "0.1.0" }
  ]
}
```

记 `dshVersion` 和 `nodeVersion` 是关键 —— 将来想复现当年的环境，
这两个数字决定了"能不能跑起来"。

### `data-snapshot/`

协会数据的快照。打包前的检查清单：

- [ ] **过一遍红线** —— 整改材料、关联方信息、举报内容、内部汇报，
      **一个都不许进**（见 [`../../GOVERNANCE.md`](../../GOVERNANCE.md) 第五节）。
- [ ] **个人隐私** —— 成员联系方式、身份证号之类，如果数据里有，
      要确认归档范围和访问权限。
- [ ] 确认快照是**只读**的（不要让人误以为这是当前数据）。

> ⚠️ **快照不是备份。** 它是"留个证据"，不是"用来恢复的"。
> 真正的备份策略由协会自己定。

### `handover-note.md`

**用大白话写给下一届。** 不需要格式，不需要完整，就写你想说的：

- 哪个坑最坑；
- 哪个功能看着好其实没用；
- 你希望下一届先做什么；
- 哪个老师的哪个要求要特别注意；
- 你后悔没做的事。

**这一份往往是最有价值的文件** —— 因为它是唯一一份不试图"客观"的文件。

## 归档流程（换届 SOP 的一部分）

完整 SOP 见 [`../../HANDOVER.md`](../../HANDOVER.md)。归档这几步：

1. 跑 `scripts\doctor.ps1` —— 确认生态是健康的（不健康的存档没意义）。
2. 建 `docs/archive/<学年>/` 目录。
3. 写 `RETROSPECTIVE.md`。
4. 生成 `plugins.json`（从各包的 `package.json` 汇总）。
5. 打数据快照到 `data-snapshot/`，**先过红线检查**。
6. 写 `handover-note.md`。
7. `git tag v<学年>` —— 例如 `v2026-2027`。
8. 提交。

## 注意

**归档目录建立之后就不要改了。** 它是历史记录，不是工作区。

如果发现归档里有错，写一份新的说明放进去，而不是改原文 ——
这样"当时是怎么想的"这个信息不会丢。
